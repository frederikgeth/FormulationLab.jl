# Repeated SDP sparsity panel

This panel repeats every profile three times with Mosek 11.2, one solver thread,
strict ``10^{-9}`` interior-point feasibility/gap tolerances, and a 120 s limit.
Reported times are medians of fresh model builds and solves. Inputs and reported
objectives use SI units; model coordinates use a 10 kVA per-unit base.

The IVR rows use each prepared radial ENWL feeder unchanged. The BranchFlow rows
use the same prepared feeder with one named line duplicated as a parallel
circuit, recorded in each JSON artifact. That controlled modification activates
the conditional global voltage closure. IVR and BFM objectives in this panel are
therefore **not** values for the same network; comparisons are only within an
ordering pair or a dense/chordal BFM pair.

## BranchFlowSDP voltage closure

| Buses | Live voltage order | Dense / auto / cap-12 status | Dense / auto / cap-12 variables | Dense / auto / cap-12 solve median (s) |
|---:|---:|---|---:|---:|
| 10 | 30 | slow / slow / slow | 2,958 / 2,958 / 1,926 | 0.191 / 0.190 / 0.165 |
| 11 | 33 | optimal / optimal / optimal | 3,354 / 2,619 / 2,085 | 0.103 / 0.081 / 0.066 |
| 24 | 72 | optimal / optimal / optimal | 13,506 / 5,988 / 4,926 | 0.374 / 0.250 / 0.188 |
| 45 | 135 | optimal / optimal / optimal | 41,514 / 11,817 / 9,132 | 1.185 / 0.508 / 0.430 |
| 96 | 288 | optimal / optimal / optimal | 176,802 / 26,076 / 19,608 | 4.700 / 1.112 / 0.920 |

The automatic rows use the public defaults: dense closure through order 32,
then minimum-degree chordal completion with a merge cap of 32. The cap-12 rows
force chordal completion with minimum-degree ordering. The prepared BFM support
graphs are already chordal before amalgamation (`chordal_fill_edges = 0`), so
minimum-fill produces the same cone/constraint structure and nearly identical
solve times while doing more graph work. Dense/auto/cap-12 objective differences
are below 0.0031 W on every comparison that reaches `OPTIMAL`; maximum scaled
residuals are below ``3\times10^{-8}``. This is numerical agreement, not an
exact-arithmetic certificate.

The 33-coordinate case is the first point above the automatic dense threshold
of 32. Chordal completion is already smaller and faster there. The 30-coordinate
case does not contradict the threshold because all three representations
terminate `SLOW_PROGRESS`; it supplies structural information but no trustworthy
timing or objective comparison. The panel therefore supports retaining the
current threshold rather than tuning it from a single boundary case.

The cap-12 layout is smaller and faster than the cap-32 automatic layout on all
four optimal BFM cases. This is a useful Mosek setting for similar networks, but
it is not yet enough evidence to change the solver-agnostic public default:
the panel uses one solver and a controlled synthetic parallel circuit, while the
implicit solver profile is Clarabel. A repeated Clarabel comparison should
precede a default change.

## IVRSDP ordering

| Buses | Minimum-degree status | Minimum-fill status | Fill edges, degree / fill | Variables, degree / fill | Solve median (s), degree / fill |
|---:|---|---|---:|---:|---:|
| 10 | `OPTIMAL` | `OPTIMAL` | 57 / 57 | 803 / 803 | 0.028 / 0.029 |
| 11 | `OPTIMAL` | `OPTIMAL` | 66 / 66 | 424 / 424 | 0.013 / 0.013 |
| 24 | `SLOW_PROGRESS` | `SLOW_PROGRESS` | 549 / 549 | 6,353 / 6,041 | 0.818 / 0.938 |
| 45 | `OPTIMAL` | `OPTIMAL` | 333 / 324 | 3,440 / 3,522 | 0.143 / 0.147 |
| 96 | `OPTIMAL` | `OPTIMAL` | 901 / 780 | 9,530 / 9,007 | 0.634 / 0.518 |

Minimum-fill helps the 96-bus cone structure and solve, is neutral on the two
smallest cases, and does not improve the 24- or 45-bus outcome. On the 24-bus
case an indivisible clique has order 14 even though the merge cap is 12; a merge
cap cannot split an original maximal clique. The mixed evidence supports keeping
minimum-degree as the deterministic default and minimum-fill as an explicit
target-specific experiment.

## Dataset scope

The local draft-data collection contains a genuinely meshed `MVLVmeshed` case,
but it has 3,409 buses and 40 cycles, and its README records an important parser
limitation: OpenDSS open-switch commands are not preserved, so all 38 restored
switches appear closed unless corrected after parsing. It is valuable future
large-scale work, but it is not a controlled substitute for this panel.

Raw repeated samples and complete provenance are retained in:

- `sdp_sparsity_10bus_2026-09-22.json`;
- `sdp_sparsity_11bus_2026-09-22.json`;
- `sdp_sparsity_24bus_2026-09-22.json`;
- `sdp_sparsity_45bus_2026-09-22.json`; and
- `sdp_sparsity_96bus_2026-09-22.json`.

The matching Markdown files are generated by
`examples/benchmark_sdp_sparsity.jl`.
